Aevatar FDE Blueprint · draft v1

把 aevatar 改造成 FDE 实施平台

FDE（Forward Deployed Engineer）在客户现场用平台交付企业级 agent 方案；平台把每一单 bespoke 交付收割成可复售模板。本方案定义了让这个循环在 aevatar 上成立的七个工作流与四个阶段。

2026-08-25 owner: eanzhao 完整方案见仓库 aevatar-fde-blueprint
01

核心判断

aevatar 的能力本体（动词侧）已是一流——typed 准入、风险分级、sealed profile、灰度治理；缺的是数据本体（客户业务对象层）与收割机制（bespoke → 模板的回路）。企业 agent 试点最常死于集成、权限、审计——后两者 aevatar 天然带着，"demo 即 production skeleton" 在这个平台上成立。

  • FDE 成立的唯一判据：现场经验回流平台的速度快过交付人头的增长。回流断掉，FDE 就是换名字的咨询。
  • 客户业务对象（订单/工单/设备）在平台内尚无建模位置——补齐它，agent 就从"每轮现场拉数"升级为"站在治理过的对象上读写"，防幻觉从 prompt 补丁变成架构约束。
  • 私有化不是先决条件：近期 hosted + hybrid（出站隧道、客户侧执行节点、签名 webhook）即可开展交付；single-tenant VPC 托管是中期工程题。
02

七个工作流

WS-A · P0

数据本体层（Scope Ontology）

为每个客户 scope 建模业务对象：object type + typed property + link + action，由已准入操作供数与写回；agent 获得 object query / link 遍历 / 受治理的 action 工具。

WS-B · P0

FDE 交付工作台

交付包成为数据（registry + 版本化），跨 artifact 的 capability manifest 可 diff 可评审，bootcamp playbook 与单一 runbook 收敛部落知识。

WS-C · P1

评测与信任

shadow replay 评测、发布回归门禁、eval 化验收；统一 agent 变更审计账本与高风险 action 影响预览。

WS-D · P0/P1

身份与权限完备化

消息渠道发送者绑定的收尾硬化（未绑定发送者降权目录）、组织级连接、准入流程"复制税"工具化。

WS-E · P1/P2

部署形态梯度

Tier1 hybrid 硬化（隧道/执行节点 fleet 化）→ Tier2 single-tenant VPC 部署 kit → Tier3 数据驻留（按单触发）。

WS-F · P2

客户端集成 SDK

从读模型契约生成 typed SDK（异步确认 + 版本水位轮询内建）；本体落地后升级为真正的 OSDK 形态。

WS-G · P0 制度

经济回路

每单必开 harvest review，模板目录与复用率/边际成本度量；平台自带的 agent 化交付技能升级为 "AI FDE" 产品能力。

03

四个阶段

第 0–1 月

Phase 0 · 零平台代码 立即可做

runbook 收敛；用现有 hybrid 机制打样 1–2 个真实交付；harvest review 制度落地；基线指标。

第 1–3 月

Phase 1 · P0 三件套

Scope Ontology MVP（含人工评测集对照）；渠道权限收尾验证；package registry；delivery acceptance 出路。

第 3–6 月

Phase 2 · 评测与集成

replay 评测与发布门禁；capability manifest 与 proposal 流转；SDK v1；准入工具化。

第 6–12 月

Phase 3 · 部署梯度与本体完整化 依赖前序

执行面 fleet 化与 VPC 部署 kit；link 遍历与 action 写回接通审计账本；度量闭环出趋势。

04

组织与判据

一个 engagement 一个 pod：Delta（交付工程师，与平台工程师同一技术标准）+ Echo（行业/客户侧专家）+ 共享的平台收割 owner（主持每单 harvest review，把可复用产物推进 registry 与 roadmap——回流循环的执行者）。

交付节奏对标 bootcamp：真实数据、真实权限，1–5 天产出生产骨架而非 demo；验收基线即首个评测集。

四个代理指标盯住唯一判据：交付周期中位数 ↓、模板复用率 ↑、每单边际成本 ↓、harvest 产出率 >0。模板复用率上升且边际成本下降而人头不增 = FDE 是产品战略；否则是在做咨询。
